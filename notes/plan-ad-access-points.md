# Plan: the prototype's gradient access points on the reverse-mode engine

Status: **open, order proposed, not yet agreed** (2026-09-28; item 2 done and item 1 corrected 2026-10-12). The engine is #648's; the access points are the ones the #553 prototype shipped ([its list](https://github.com/traitecoevo/plant/pull/553#issuecomment-5186131586)). #553 is a prototype and will not merge, so anything a downstream user relied on from it has to be rebuilt here.

## Where #648 stands against the prototype

| prototype access point | what it gives | prototype models | in #648 |
|---|---|---|---|
| `stand_gradient(scm, metrics, traits, species, feedback)` | metrics × traits Jacobian of emergent stand outputs | FF16, TF24f all metrics; TF24 offspring only | **Partly.** TF24 and FF16 (FF16 since `feature/ff16-stand-gradient`, 2026-10-12). Three census metrics at the final time: `leaf_area`, `mass_above_ground`, `area_stem`. No `species` or `feedback` argument. The one mode is the whole-run total, the analogue of `feedback = "resident"`; there is no frozen-canopy mode. K93 and TF24f refuse by name. |
| `offspring_production_gradient(scm, traits, species)` | d(offspring production)/d(trait): the invasion or selection gradient | FF16, TF24, TF24f | **Missing.** Offspring production is not a census metric. |
| `stand_state_jacobian(scm, traits, species)` | per-cohort state × trait Jacobian, an escape hatch for any downstream metric | FF16, TF24 | **Missing.** `census_trait_tangent` computes a directional derivative internally, but no per-cohort state Jacobian is exposed. `stand_census_state_adjoint` is a test-only export and is not this. |
| `grow_individual_to_size_gradient(individual, sizes, size_name, env, traits)` | d(time to size)/dθ and d(state at that time)/dθ for one plant in a fixed environment | FF16, TF24f | **Missing.** |
| `birth_rate_gradient(scm, metrics, species)` | d(census)/d(birth rate) and d(R0)/d(birth rate) | FF16 | **Missing.** Birth rate is not among the 48 columns. |

## What each needs on this engine, and a proposed order

Ordered by what a calibration or selection-gradient user needs first, and by what the engine already nearly does.

1. **Offspring production and R0 as differentiable metrics: DONE for FF16 on `feature/ff16-fitness-gradient` (#658), TF24 still open.** The engine's metric list (`SCM::stand_metrics`) carries census sums and per-species fitness side by side; a model opts in with `differentiable_fitness = true` once its fecundity channel is refereed, and TF24 has not been (its `S_D` would also need to become a column). Original note, which still holds for how the quantity is shaped: Fecundity is an ODE state, so both are functions of the final state and the reverse pass already accepts any such function as its seed. ⚠️ They are NOT a row in `census_metrics()`, though: a census metric is a per-plant quantity weighted by the cohort's density, integrated over cohorts and summed over species, while R0 reads each cohort's survival-weighted fecundity, weights it by the patch frequency at the cohort's birth (`weighted_fecundity`, not density), and is reported per species (`Patch::net_reproduction_ratio_for_species`). So this needs a second, patch-level metric kind -- one function of the final state returning one value per species -- beside the census, with its own seed rows and the same refusal and control discipline. It is still the fitness quantity and the first thing regnans asks for (plant#650 E1).
2. **FF16 as `Censusable`: DONE on `feature/ff16-stand-gradient`.** `FF16_Pars`, `FF16_Strategy` and `FF16_Environment` are templates on the scalar with the whole model in the header; the seed height goes through the implicit function theorem as TF24's does; `eta` and `S_D` are undifferentiable; PPA is refused at the rebind. Forward output is bit-identical. It needed odelia 0.7.1 (a run whose first state is empty). Decisions that bind later work: (a) **referee a new model's gradient by a central difference of runs pinned to the recorded `ode_times` and `ode_step_sizes`** -- that is the function the sweep transposes, and it agrees to 1e-5 or better where a free difference scatters at 1e-2; no model-specific ladder is needed for that; (b) the R entry points choose the model off the SCM's class (`census_backend()` in `R/stand_gradient.R`), so a new model adds its `_<model>` exports there and nowhere else. K93 is not done and nothing asks for it. Cost on FF16: a three-metric gradient is ~40x a forward run (0.39 s against 0.01 s on a 10-year stand), because FF16's forward step is cheap and the tape's per-step overhead is not; on TF24 the same ratio is ~3x.
3. **Birth rate as a column: DONE for FF16 on #658.** Carried at the working scalar on the strategy (`FF16_Strategy::birth_rate_`), read by the patch through `birth_rate_at(t)` at the inflow condition and the offspring integral; a variable birth rate stays a double driver and has no column. The per-species column count is now a member (`ad_column_count()`), so TF24 keeps its constant. Original note: It enters through the introduction density, which is the insertion map the sweep already transposes, so it is a parameter of `apply_insertion` rather than a new mechanism. It is needed for d(R0)/d(birth rate).
4. **Frozen-canopy feedback, the rare-mutant invasion gradient: DONE for FF16 on #658.** The row-kind refusal in odelia landed in 0.7.0 (a subdivided `step_to` row is refused); 0.7.2 makes a replay keep the rows it loaded and hands the sweep's first stage its row. One plant-side piece remains model-agnostic but worth knowing: an insertion and the first rates after it have no row, so the SCM hands the patch the field in force at each introduction time (`Patch::set_introduction_fields`), looked up by exact time. Without it the mutant's own canopy leaked into the derivative (its `k_I` column read -0.097 where the difference is exactly 0). Original note: This is the selection gradient adaptive dynamics needs. It sweeps a `run_mutant` replay with the resident light held passive. The replay path is already odelia's recording, so the sweep is the same; the difference is which System is active. ⚠️ `run_mutant` uses `step_to`, which subdivides on rejection, and odelia's sweep would transpose a subdivided row as one step (review §5.1 defect 1). A row-kind refusal in odelia has to land first.
5. **`stand_state_jacobian()`.** It exposes `census_trait_tangent`'s forward tangent per cohort and state, instead of contracting it with a census metric.
6. **`grow_individual_to_size_gradient()`.** It needs a single `Individual` in a fixed environment, the implicit function theorem on the time-to-size root, and a tangent of the state there. It is independent of the stand machinery.
7. **TF24f as `Censusable`.** The prototype's TF24f resident census gated at patch lifetime ≳ 5, so expect the same stiffness here.

## Decisions needed before starting
