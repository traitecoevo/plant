## Context

The use case is one patch run continuously under one stationary realisation of a rainfall-pulse series, with no disturbance regime. Mutant cohorts are introduced across a window $[T_1, T_2]$ and their lifetime offspring production is averaged over arrival time: $R = \frac{1}{T_2 - T_1}\int_{T_1}^{T_2} \tilde R(t_0)\,dt_0$, run to $T_2 + L$ so the last arrivals live out their lives. That replaces the FF16 patch-age weighting, and every part of the fitness note's §4 and §6 sits on this mode.

What the code does today, which the design builds on rather than replaces:

- **A run is a schedule of stops.** The event queue of #632 holds one `schedule_entry` per instant ([node_schedule.h:119](../inst/include/plant/node_schedule.h#L119)) with its actions ranked and its species grouped; `SCM::run_next` ([scm.h:587](../inst/include/plant/scm.h#L587)) pops the entry at the current time, applies the actions, introduces the species, and integrates to the next entry. The run ends when the queue is consumed, and the last leg ends at `max_time = max_patch_lifetime`. Node introduction is already an event type ([node_schedule.h:36](../inst/include/plant/node_schedule.h#L36)).
- **Nodes are appended and never removed**, so a long run's cost grows with every cohort introduced. On the birth-date coordinate (#590, `control$node_density_in_birth_date`, [control.h:66](../inst/include/plant/control.h#L66)) the node list is the quadrature grid of the competition field, the resource uptake, the census and the fitness integral ([species.h:326](../inst/include/plant/species.h#L326), [:498](../inst/include/plant/species.h#L498), [:791](../inst/include/plant/species.h#L791), [:840](../inst/include/plant/species.h#L840)), and a cohort's density changes by mortality alone ([individual.h:257](../inst/include/plant/individual.h#L257)).
- **Fitness is a trapezium over birth dates.** `net_reproduction_ratio_for_species` ([patch.h:930-938](../inst/include/plant/patch.h#L930-L938)) integrates `fecundity_k × patch_density_at_birth_k × S_D` ([node.h:84](../inst/include/plant/node.h#L84)) over the node times, scaled per node by `birth_rate_at(t_k)` for offspring production ([patch.h:943](../inst/include/plant/patch.h#L943)). `patch_density_at_birth` is stamped at introduction from `survival_weighting->density(t)` ([patch.h:1245](../inst/include/plant/patch.h#L1245)); `pr_survival(t)` multiplies the fecundity rate ([node.h:49](../inst/include/plant/node.h#L49)) and the inflow condition ([patch.h:1045](../inst/include/plant/patch.h#L1045)). The regime is built in `Parameters::validate()` ([parameters.h:126](../inst/include/plant/parameters.h#L126)): Weibull for `patch_type == "meta-population"`, otherwise `No_Disturbance` (density 1, survival 1).
- **Resume on develop had gaps, which this work closes (design 3).** `export_patch_state()` and `set_initial_state()` carried the flat ODE state (nodes, then the environment, which for TF24 is the five soil layers and the five flux accumulators), the per-node birth bookkeeping and the residual introduction schedule, and `Patch::set_initial_state` loaded them. The gaps: a pinned replay across the resume gap was refused; `NodeSchedule::r_set_ode_steps` demanded a first time of exactly zero; `Patch::reset()` let `environment.clear()` zero the clock when `initial_state` was empty; `make_initial_state()` stamps every node with time 0, which the birth-date coordinate refuses for more than one node per species; and the export did not carry residual events.
- **The reverse pass has no run-length tape.** odelia 0.7.1's tape holds one step at a time ([adjoint.hpp:15](../../odelia/inst/include/odelia/adjoint.hpp#L15), [ode_solver.hpp:511](../../odelia/inst/include/odelia/ode_solver.hpp#L511)). What grows with the run is the row store, one `step_record` per accepted step ([ode_interface.hpp:242](../../odelia/inst/include/odelia/ode_interface.hpp#L242), [ode_solver_internal.hpp:387](../../odelia/inst/include/odelia/ode_solver_internal.hpp#L387)): the state plus six per-stage solved rows, which for TF24 is one 16-byte `leaf_solved_point` per node per stage ([tf24_strategy.h:487](../inst/include/plant/models/tf24_strategy.h#L487)) plus the recorded field when an invasion keeps it. `solve_adjoint` sweeps any sub-range of rows ([ode_solver.hpp:446](../../odelia/inst/include/odelia/ode_solver.hpp#L446)), and a recording starts where the run starts ([ode_solver_internal.hpp:90](../../odelia/inst/include/odelia/ode_solver_internal.hpp#L90)).
- **Cost.** TF24's rate evaluation is a leaf solve per node per stage; a 105-year run on the default schedule costs about a minute (test-scm.R's own note). Pulses add a leg boundary each, and a leg inherits the previous leg's step size, which is the measured trigger of the soil column's blow-ups (NEWS, [Known issues](../NEWS.md#L1167); `ode_step_size_max = 0.05` is the guard).

## Decisions

1. **The regime supplies the weight; the schedule supplies the times.** A `Fitness_Window : Disturbance_Regime` with `density(t)` equal to a normalised tabulated weight on $[T_1, T_2]$ and zero outside, and `pr_survival ≡ 1`, feeds the fitness integral, the node stamps and the inflow condition unchanged. Periodic introduction is a generated schedule on the existing queue, not a new mechanism. The regime never reads the environment: R builds the germination weight from the same pulse series that drives the run, which is baked in up front (#522).
2. **A cohort leaves the integrated set one way only: by passing the absorbing height.** Each species has one top cohort pinned at the height where its strategy allocates $1 - \varepsilon$ of its maximum to reproduction (`Control$absorb_epsilon`). At every introduction instant a live cohort that has reached that height is absorbed: its share of every trapezium moves into the top cohort, which carries its density, its share of the light field and uptake, and its future seed output, and the cohort stays in the node list as a frozen zero-density grid point. That is the absorbing boundary the issue asked for: the top layer's size is fixed and only its densities move, so a stand in a constant environment has a fixed point, and nothing is discarded. A cohort whose density is already exactly zero is frozen too, which discards nothing either. There is deliberately no survival floor (Daniel, 2026-10-13): retiring a cohort below one discards the biomass old trees still hold (measured below) rather than conserving it. It was built, measured and removed; what it bought on the pulsed TF24 stand is recorded in section 7.
3. **Birth-date coordinate only.** TF24 needs it (#590) and the reverse sweep refuses the other coordinate; the top layer is refused on the height coordinate.
4. **Resume is the mechanism for everything long.** The burn-in is paid once and exported; the window run, every mutant and every gradient resume from it. The refusals that block a pinned replay or an invasion from a resumed state are removed.
5. **Two terminations on one primitive**, `SCM::run_to(t)`: a fixed horizon is `run()` with `max_patch_lifetime = T_2 + L`; convergence is a block-mean test driven from R over `run_to`, with a hard cap.
6. **History is thinned to snapshots of summaries.** The per-leg Patch copy of `collect` stays for short runs. Per-node lifetime offspring production is ODE state and is never thinned; it is lost only for absorbed cohorts, which are never window cohorts.
7. **Gradients: cut at the window boundary first.** That is the resume path with `record_trajectory = TRUE`; the burn-in state is exogenous. Short mutant runs from sampled saved states are the same mechanism with the start time sampled and one lifespan long.
8. **Bit identity.** Every capability here is opt-in (`patch_type = "fitness_window"`, `absorb_epsilon`, `snapshot_interval`, `run_to`), so a run with an unchanged set of stop times and actions is bit-identical to today's, verified with `identical()` on raw arrays for FF16, K93 and TF24 at every migration commit. Pinned since by `test-default-baseline.R`: six default runs (FF16, K93, FF16 with a harvest, an invasion and a resume, TF24) against a baseline recorded from the commit before #661 (`9f04309b`, `scripts/capture-default-baseline.R`), and in-build invariances (snapshots and a fitness window leave the trajectory untouched).
9. **Two frameworks, kept apart (Daniel, 2026-10-13).** The continuous patch to equilibrium runs under constant drivers, for every model: FF16 under constant light, TF24 under constant rainfall, a cohort a year, the top layer on, run until it is a fixed point. There a mutant needs one field, not a replay (design 6). Rainfall pulses never settle, so they belong to the other framework: one long patch, burnt in, exported, resumed through a window, with the window average as fitness and mutants by exact replay of the recorded resident.

## Design

### 1. Periodic introduction and the fitness window

The two halves of requirement 1 are different objects. Introduction *times* are a schedule: `node_schedule_times_periodic(start, end, by)` (R, beside the C++ default of [scm_utils.cpp:6](../src/scm_utils.cpp#L6)) fills `p$node_schedule_times` with a uniform grid that stops short of the run's end, which `node_introductions(p)` turns into queue entries like any other. The *weight* each cohort carries in the fitness integral is the regime's: `Fitness_Window(T1, T2, x, w)` ([disturbances/fitness_window.h](../inst/include/plant/disturbances/fitness_window.h)) returns the tabulated weight `w(t)` for $t$ in the window and 0 outside, read at the node's own birth date, so the uniform case is flat and a germination-weighted case is a table built in R from the pulse series and a trigger rule (an event-size threshold first; the form is empirical, note §9). `pr_survival` is one; `cdf`, `icdf` and `r_mean_interval` keep the base class's answers.

**Normalised over the window's own cohorts, not analytically.** The regime declares itself an arrival weighting (`is_arrival_weighting()`), and `net_reproduction_ratio_for_species` then takes the trapezium of output times weight over the trapezium of the weight alone, both over the span from the first to the last cohort with positive weight: the weighted mean of lifetime output over the window's arrivals, by the ordinary trapezium for $\frac{1}{T_2 - T_1}\int R(t_0)\,dt_0$. Two measurements decided it. An analytic normalisation, a density stepping to $1/(T_2 - T_1)$ at the window's edges over every node, read 69.56 for a 100-year window against a cohort mean of 68.87, exactly $1 + \Delta/(T_2 - T_1)$. Normalising over every node fixed that but still let a zero-weight cohort just outside the window give the first window cohort a whole interval: the resident's own strategy, run a million times rarer beside the resident with a schedule starting at the window, scored 62.56 against the resident's 62.33 on the pulsed TF24 stand, which is the first cohort's half weight to four digits (predicted 62.561). Restricted to the span, nothing outside the window enters, and a resident and an invader on the window's schedule score the same cohorts the same way; `test-fitness-window.R` asserts it on FF16 to 1e-12. Done in #661, with `fitness_window(p, start, end, weight_x, weight_y)` in R.

It is selected by `patch_type = "fitness_window"` with four new `Parameters` fields (`fitness_window_start`, `fitness_window_end`, `fitness_window_weight_x`, `fitness_window_weight_y`), built in `validate()` beside the Weibull ([parameters.h:115](../inst/include/plant/parameters.h#L115)). Cohorts born outside the window carry density 0 and contribute nothing to fitness; they are the stand. Mutants therefore need introductions inside the window only, residents throughout.

How it coexists with the queue: introductions are already events, the generator only chooses their times, and `refine_schedule` ([scm.h:782](../inst/include/plant/scm.h#L782)) bisects a uniform grid exactly as it bisects the default one and leaves actions untouched. What spacing a pulsed stand needs, and how the schedule should be refined against a pulse series, is deliberately not settled here: Andrew has found that the node schedule does not capture pulsed rainfall well and is proposing refinements, and this plan takes the introduction grid as given (non-goals). Two constraints it does impose: each refinement iteration is a whole run, so any refinement happens on a segment from a saved state rather than on the long run, and refinement with the top layer on is refused (design 2).

Test (in `test-fitness-window.R`): the regime's values and refusals; the ratio equals the R-side weighted mean of per-node output to 1e-12, for a uniform and for a tabulated weight; a 500-year periodic FF16 stand without the top layer gives the same window mean for [100, 200], [200, 300] and [100, 300] to 1e-3, while the founding century and a window ending within a lifespan of the run's end read differently; and a gradient runs on a window patch, which is what says `rebind_from` copies the window.

### 2. The absorbing top layer

Per species, with `Control$absorb_epsilon` > 0, a top cohort: one `Individual` pinned at the absorbing height, its height held (rate zero) and its other states integrated (TF24's storage, the heartwood), plus five numbers in the species' ODE block after its nodes: the density it carries, the fitness weight it carries without and with the birth-rate scaling, and the seed output each has accrued. The density and both weights decay at the pinned individual's mortality rate in the current field, so drought mortality and pulse-driven uptake act on the layer as on any cohort; the seed output accrues at its fecundity rate times the patch survival, as a node's does.

**Absorption.** At each introduction instant, inside the insertion map that `run_next` and the sweep's `apply_insertion` both apply (`Patch::absorb_tall`, then the push), every live cohort bar the youngest with height at or above the absorbing height is absorbed, unless an arrival weighting weights it (then it keeps its node, so every cohort the fitness integral reads keeps its own lifetime output). Its quadrature weight on the birth-date grid, $c_k = (\tau_{k+1} - \tau_{k-1})/2$, times its density goes into the layer's density; $c_k \times$ patch density at birth $\times S_D \times$ survival $/$ patch survival at birth goes into the fitness weight (and the same times the birth rate at birth into the other); its non-height states are averaged into the layer's by density; and its density is set to the exact-zero sentinel a never-established cohort carries. The youngest is never absorbed because its quadrature weight is not final until the next cohort arrives.

**Why the cohort stays as a grid point.** Setting a node's value to zero while keeping its abscissa removes exactly $c_k f_k$ from every trapezium and leaves its neighbours' intervals untouched, so the transfer conserves total density, the field's reduction, uptake and the census to rounding at the instant, wherever in the list the cohort sits. Measured: a stand with 219 cohorts above the height loaded with absorption on loses nothing of its total density to fifteen digits as all 219 go at once. It also means the node structure never changes: a replay, a resume or a sweep finds the same nodes, and an absorbed cohort is recognised from the state it is loaded with, so no record of which cohorts went is needed (the plan's earlier design, a prefix merge with an absorption log, is not needed). The node list still grows; the cost does not, since a frozen cohort is not evaluated.

**Readers.** The layer is a point mass outside the trapezia: added to each split's running sums in `field_splits` and `compute_competition_and_slope`, to `consumption_rate` and to `census_integral`, as density times the pinned individual's quantity; `height_max` includes its height, so the light field spans it; the fitness integral adds its seed output to the trapezium over nodes (the output an absorbed cohort accrued before it went stays on its node). Snapshots carry its density. A gradient refuses it until absorption's transpose is written.

**The height ordering.** A frozen cohort's height stops while younger ones grow past it, which broke the decreasing-height ordering the fast field build relies on and made a run with frozen cohorts slower than one without (section 7). With the layer on, the height scan leaves frozen cohorts out (they contribute exactly zero) and the walk's early exit steps over them; competition agrees with the old path to 3e-11.

Interaction with #590: natural. The top layer is off the birth-date grid, there is no compression term, and absorption changes no abscissa. On the height coordinate density can rise through the transport term and the layer would have to be a grid point at the top of the height axis, a different construction; it is refused there, and on K93, which declares no maturation height.

Where the boundary sits: set from the strategy's allocation to reproduction, not chosen by hand. FF16 and TF24 allocate a fraction $r(h) = a_{f1} / (1 + e^{a_{f2}(1 - h/h_{mat})})$ of surplus to reproduction, so above the height where $r$ reaches $1 - \varepsilon$ of its maximum, $h_{abs} = h_{mat}\,(1 + \ln((1 - \varepsilon)/\varepsilon)/a_{f2})$, growth's share of surplus is $1 - (1 - \varepsilon)\,a_{f1}$: within $\varepsilon\,a_{f1}$ of its floor, and $\varepsilon$ itself only where $a_{f1} = 1$ (FF16's and TF24's default). The height is refused unless $h_{mat}$ and $a_{f2}$ make it positive and finite, and $\varepsilon$ must be zero or in $(0, 0.5)$. FF16's defaults give $h_{abs} = 1.138\,h_{mat} = 18.89$ m at $\varepsilon = 10^{-3}$, and the unretired continuous stand's top stalls at 18.95 m (section 7): the rule finds the asymptote the stand edges toward. A strategy declares its own `asymptotic_height(epsilon)`; one that declares none has no top layer. What the boundary costs: the pinned individual's rates are those of $h_{abs}$, a fraction $\varepsilon$ short of the asymptote's.

Rejected: absorption by age (the absorbed cohort keeps growing and no fixed point exists, which is what the issue calls "edging upward indefinitely"); an evolving density-weighted mean height instead of a pinned one (same problem); removing absorbed nodes from the list (a prefix merge needs an absorption log for the sweep and a replay, and an interior removal breaks the trapezia; a frozen grid point needs neither); a survival floor as the way out (it discards the biomass old trees hold; built, measured in section 7, removed); a check at every step (state-triggered inside the stepper, which a solver hook can observe but not restructure).

Tests (`test-absorb.R`): off by default; refused on the height coordinate, at $\varepsilon \ge 0.5$ and on K93; total density conserved to 1e-13 as more than 100 cohorts are absorbed at once, with the layer at exactly the absorbing height; every cohort that leaves the integrated set while carrying density stands at the absorbing height, and its height never moves again; a second run on the same SCM starts without the first's layer; a harvest takes its fraction of the layer; a spent layer empties; a frozen cohort's height does not move the field, out of order or not; refinement, a bad epsilon and a bad absorbing height are refused; two species keep a layer each, at their own heights; TF24 absorbs at its own height; a continuous FF16 stand with the layer reaches a fixed point (top of the stand to 1e-7, density to 1e-8) with fewer than 150 cohorts integrated, and its census and fitness agree with the unbounded stand to 1e-5; window cohorts are never absorbed; the layer survives an export and a resume; a gradient refuses it. With `absorb_epsilon` zero every run is bit-identical to develop.

### 3. Restart from a saved state

What the export already carries for a TF24 patch: every node's ODE state, the environment's ODE state (soil water by layer and the five accumulators), the per-node birth date, patch density and survival at birth, and the residual introduction schedule. What the resumed run rebuilds: the light spline, the boundary node, the rates. What it loses: `birth_growth_rate` per node, which only the Jacobian report reads.

What a continuous-patch resume adds:

- **Residual events.** Events are a `run_scm()` argument by design (plan-events §2), so `export_patch_state()` gains `events`, the events at or after the export time, read off `scm$events`, and the caller passes them back. Pulses, germination and season-end events all ride this field.
- **The top layer.** Its ODE state, the pinned individual and its five numbers, travels in the species block; nothing else is needed, since an absorbed cohort is recognised by the state it is loaded with.
- **The window.** On `Parameters`, so it travels.
- **A seed bank, later.** A per-species scalar in the species ODE block, so the export carries it without a format change.

Fixes the resume path needs, each small:

- `Patch::reset()` honours `initial_time` with an empty `initial_state` ([patch.h:689](../inst/include/plant/patch.h#L689)); an empty mutant patch has to start at $T_1$.
- `r_set_ode_steps` accepts a first time equal to `initial_time` ([node_schedule.cpp:271](../src/node_schedule.cpp#L271)).
- `run_next` replays the gap to the first residual entry by program instead of refusing ([scm.h:595-608](../inst/include/plant/scm.h#L595-L608)).
- The patch density at birth is re-stamped on import from the run's own regime (found by the workflow below: a cohort seeded from a "fixed" burn-in into a window run carried the burn-in's stamp of one and weighed itself into the window's average; under the regime that stamped it the re-stamp is the same number, and the baselines say so). The survival at birth is re-stamped the same way (a review fix on #661): a resumed cohort's fecundity rate divides its patch survival now by its survival at birth, so both have to be the resuming regime's.
- `run_mutant` ([scm.h:708](../inst/include/plant/scm.h#L708)) from a resumed resident: the resident's recording starts at $T_1$, and the mutant's parameters carry no initial state, `initial_time = T_1` and a schedule inside the window. Found while building it: the patch seeds itself at every `reset()` from its OWN copy of the parameters, and `run_mutant` replaced only the strategies, so an invader of a resumed resident started as a copy of the resident's exported stand; the invader now takes the whole parameters (`Patch::overwrite_parameters`). Invisible from empty, where there is nothing to seed.

`make_initial_state()` ([scm_support.R:208](../R/scm_support.R#L208)) is not the resume entry point: it builds a synthetic size distribution at age 0 with every node stamped at time 0, which `check_birth_dates_distinct` refuses on the birth-date coordinate for more than one node per species. The fitness note's "restart with `make_initial_state()`" should read `set_initial_state()`.

A resumed run is not bit-identical to a straight one: the step-size memory restarts at `ode_step_size_initial` at the seam. Section 7 measures the gap.

### 4. Termination

`SCM::run_to(t)` runs legs until the patch time reaches `t` or the queue is consumed, then refreshes the `patch` snapshot (`run()` does this only after its loop), so a caller can read the stand between legs without a Patch copy per step. A run that has not begun begins first, as `run()` does, so a sequence of `run_to()` calls is a `run()` leg for leg (tested bit for bit); `run()` always starts over. `SCM$complete` says whether the schedule was consumed, and `export_patch_state()` works wherever `run_to()` stopped, keeping an action due at that instant pending, since `run_to()` stops on arrival before the instant's actions run. `run_scm(p, ..., run = FALSE)` builds an SCM to drive this way.

Fixed horizon: `run()` with `max_patch_lifetime = T_2 + L`, where $L$ is the longest lifespan the user believes in; the event horizon check already refuses events past it.

Convergence: a block-mean test, `run_until_converged(scm, block, tol, t_max, statistics)`. Over blocks of $B$ years (default 20, a few correlation times of the driver) take the mean over the block's snapshots of the chosen statistics: the species' carried density summed, the tallest cohort with density, the live-cohort count, and every entry of the environment's state (soil water per layer and the accumulators for TF24); converged when the last `window` block means (default 3) of every statistic lie within `tol` (default 0.02) of each other, relative to their largest magnitude, or within `tol_abs`; the range over a window rather than consecutive changes is what lets a steady drift accumulate into the test. By default the environment statistic leaves out TF24's accumulators, and the tallest cohort is left out with the top layer on, since both settle whatever the stand does (#661 review). A settled stand statistic is not a settled fitness: a drift below `tol` per window passes, and fitness can be far more sensitive than the statistic (section 7's TF24 constant-rain stand); check the quantity of interest at two times; stop at `t_max` regardless, or when the schedule is consumed, and say which. Driven from R over `run_to`, with the trace of block means and relative changes returned. The census metrics are not in the statistic because K93 declares none and the environment's state carries what the soil contributes; add them per model if a stand's leaf area is the slow variable. The referee is external: the soil-water histogram of the converged run against the closed-form density of the fitness note's §5. On the 400-year periodic FF16 stand of the test it converges well before the cap at the defaults.

With the top layer on and periodic introduction, the node count is bounded by the years a cohort takes to reach `absorb_height` divided by the spacing, plus the window cohorts, so a converged stand has a fixed cost per step; and because the top layer's size is pinned, a constant-driver stand has a true fixed point for the test to find.

### 5. History

Today `collect = TRUE` pushes a copy of the whole Patch at every leg ([scm.h:569-578](../inst/include/plant/scm.h#L569-L578)); under twenty pulses a year that is twenty copies of a several-hundred-node patch per simulated year and is not usable for a long run.

`snapshot_interval` (years) on the SCM, done in #661. At the run's start and at the first leg boundary at or past each later multiple, the run pushes a summary: time; per species the node count, the cohorts with density, the retired cohorts, the tallest cohort with density, the trapezium of the carried density over the birth-date grid, and every node's lifetime offspring output; and the environment's own state, which for TF24 is the soil water by layer and the five flux accumulators. `scm$snapshots` is the list and `tidy_snapshots()` flattens it to a species table, an environment table and the fecundity vectors. `collect` is unchanged for short runs, and the event log is unchanged because it is bounded by the event count. The census metrics are left out for the reason above.

Per-node lifetime offspring production is ODE state (`offspring_produced_survival_weighted`), so it is kept by the run itself whether or not anything is recorded. The only cohorts whose per-node value is lost are absorbed ones, which by design 2 are never window cohorts.

### 6. Reverse-mode gradients over a long run

There is no run-length tape to cut. The cost of a sweep is the row store and the walk over it: per accepted step about $8(8n + 10) + 6(16n + 1600)$ bytes for $n$ TF24 nodes (state, six solved rows, the field when kept), and six stage re-evaluations per row on the way back.

**Cut at the window boundary.** Resume at $T_1$ with `record_trajectory = TRUE` ([scm.h:125](../inst/include/plant/scm.h#L125)); the recording's row 0 is the resumed state and `census_trait_gradient` ([scm.h:1187](../inst/include/plant/scm.h#L1187)) sweeps rows over $[T_1, T_2 + L]$ only. What the cut drops is the dependence of the state at $T_1$ on the traits. For a rare mutant in a frozen resident field that dependence is exactly zero, so the cut is exact; for the resident's own fitness it treats the burn-in stand as fixed, a deliberate approximation that has to be stated beside any resident gradient.

**Short mutant runs from sampled saved states.** The same mechanism with $t_0$ sampled: $K$ exported states along the stationary run, and for each a resident recording of one lifespan $L$ (`resident_recording` persists on the SCM across mutants, [scm.h:141](../inst/include/plant/scm.h#L141)), then per mutant one $L$-year replay and one $L$-year sweep. The row store is bounded by $L$ rather than by $T_2 - T_1 + L$, and the runs are independent. What it needs beyond the cut: the resume fixes of design 3 and the sampling design (stratified by soil-water state, note §4.5).

**Mutants at a fixed point need one field, and are built.** A stand at a fixed point (constant drivers; on the birth-date coordinate with the top layer, without which the top keeps edging up) makes one field, and a mutant there is one cohort integrated in it until it is dead: no recording, no replay, no rerun of the resident. `SCM$run_mutant_held(p)` takes the resident's field from the state it has reached (`Patch::current_field()`, built afresh), and the patch holds it at every rate evaluation of the invaders' run (`Patch::hold_field()`), whatever the time; the environment's own rates are written as zero, so a TF24 field holds its soil too. The field is held by value, not pointed at, because a pointer into the patch's own member dangles in every copy (#589) and the solver integrates a copy. `fixed_point_fitness(scm, p, traits)` is the R face: one cohort per invader, born at time zero, run for `lifetime` years, refused if any is still alive, scored by its lifetime output per seed. The invaders take their own steps, so it covers every model and the top layer. ⚠️ The introduction grid must make the stand a fixed point: between two introductions the field swings, and a grid that is too coarse makes the stand a periodic orbit whose held field, taken at an introduction, is the top of the swing (section 7; FF16 at $b^*$ needs a cohort every quarter year).

The cut comes first because it is the degenerate case ($K = 1$, $t_0 = T_1$) and because nothing new is built for it. TF24's fitness metrics are not yet differentiable (TF24 opts out of the fitness metrics; `S_D` and `birth_rate_at` are doubles), which is the line of work in #658, not this plan's.

**Two things the landscape run found, both for step 6.** First, `run_mutant()` refuses on the pulsed TF24 stand, and the refusal is a symptom. Every invader, a copy of the resident's own strategy included, stops at the same step, 1.3 years into the window, with a seedling's storage at $-3 \times 10^{-7}$ kg. The resident's own cohort passed that step, and the resident's pinned rerun that builds the recording matches its adaptive run to 3e-11, so the recording is sound. The invader is not: a copy-invader's cohort grows 7 % slower than the resident's own from the instant it is introduced, and by a quarter year its height is 1.5 % low and its storage 6 % low. It is the pulses. From empty, with one cohort and identical node lists, the copy drifts by 0.09 % at 0.3 years and 3 % at 1.3; under constant rainfall it matches to 9e-10, resumed or not, with the top layer or without. A replay never applies an event action: `advance_recorded` walks the resident's rows and applies introductions, and only `run_next` applies actions ([scm.h:781](../inst/include/plant/scm.h#L781)); `run_mutant` also rebuilds the invader's schedule from its parameters alone ([scm.h:900](../inst/include/plant/scm.h#L900), the same on develop). On FF16 a copy-invader of a stand with two harvests is never harvested, and carries 14 to 55 % less cumulative mortality than the resident. Putting the events back into the invader's schedule changed nothing, since the replay does not apply them; how a pulse reaches the invader's rates when every stage loads the resident's soil is not found. #658 adds the sweep's half of the field bookkeeping, `introduction_fields` for the instants where a sweep has no row to load and `field_fresh` so a stale field lapses; neither applies an action either. What follows for Andrew's two fixes: a storage basis that cannot go negative, or a replay that subdivides a refused step, would let the invader run but not make the copy score the resident. Until then the landscape script runs each mutant as a second species at a birth rate $10^{-6}$ of the resident's, simultaneously with the resident in a full run from the export: the field it sees is the resident's own at every stage, at the price of the resident's full cost per mutant, which is the measurement's price and not the design. Second, the resident's own pinned replay on this stand gives the same ratio to six digits but not a bit-identical final state, where FF16's does; the suspect is the subdivided `step_to` at an interval's end, and it has to be settled before a TF24 sweep is trusted, because the sweep transposes the recorded steps.

### 7. What the pilot measured

Run on 2026-10-12 with the pilot script `measure.R`, since retired; it is in #661's commits, [at `c410510b`](https://github.com/traitecoevo/plant/blob/c410510b0162ca701101f58ae64c8f6295e594b8/notes/scripts/continuous-patch-519/measure.R). Every later measurement in this section is a task of one of two scripts that share [`common.R`](scripts/continuous-patch-519/common.R): [`long_patch.R`](scripts/continuous-patch-519/long_patch.R), the pulsed framework of decision 9, and [`fixed_point.R`](scripts/continuous-patch-519/fixed_point.R), the constant-driver one. `PLANT_519_TASK` picks the tasks; each script's header lists them and their settings. Both write their tables to `notes/scripts/continuous-patch-519/output/`, which is not tracked: rerunning a task regenerates them. plant `a9e7f8b6` (develop) with odelia 0.7.1 and phylloptim 0.10.1, Apple M5 Max.

**Setup.** One TF24 species (lma 0.0825, default `hmat`), `patch_type = "fixed"` (no disturbance regime), birth rate 1, one cohort introduced per year, birth-date coordinate, `ode_step_size_max = 0.05`, the continuous rainfall driver off, and 19,911 rainfall pulses over 1000 years from a Poisson process at 20 per year with exponential depths of mean 14 mm (277.7 mm per year), seed 1. **The stand.** Century block means of the per-decade values: total density 0.80 to 1.12 individuals per m² with no trend from the first century on, surface soil water 0.18 to 0.22, 17 to 19 cohorts with density; the per-decade values swing between 0.13 and 1.7 per m², which is pulse-driven recruitment. The 100 seams of the long run needed nothing re-supplied beyond the chunk's events.

**Not exercised.** The queue held about 210 events per chunk, so the quadratic build at $10^4$ events in one queue (hazard 4) was not measured. One species, one realisation, one cohort rate.

**What it decides.**

- Bounding the cost comes first. The top layer does it on this stand (section "Bounding the cost", below): 0.05 s per year at 200 years against 0.47 unbounded, because canopy cohorts are absorbed on reaching the height and the many that die young reach exactly zero density and are frozen.
- A cohort leaves the integrated set only by passing the absorbing height; there is no survival floor (decision 2). This pilot was first run with one, which is how the comparison below exists.
- Burn-in for this stand is about a century; the decade-scale swings in density set the correlation time the window length has to average over.
- For a sweep, the row store at 1000 cohorts is about 160 KB per accepted step, 14 MB per simulated year, so a 300-year window plus lifespan is about 4 GB. Absorbed and frozen cohorts stay in the state as grid points, so the row store grows with every cohort introduced; it is the cost per step that the top layer bounds.

**The workflow end to end, measured.** `long_patch.R`'s `workflow` task, on the same stand and series, with the top layer at $\varepsilon = 0.05$ (17.57 m): burn-in under no regime with `run_until_converged(block = 50, tol = 0.15)` on the summed density, the tallest cohort and the five soil layers, export, resume into `fitness_window(T1, T1 + 100)` run 50 years past the window, then the arrival-output statistics (`output/workflow-burnin.rds`, `output/workflow-window.rds`).

- Burn-in converged at 200 years in 9 s: block means of density 0.66, 0.63, 0.61, 0.62 per m², the tallest cohort 16.0 m in the first block and 17.57 m, the absorbing height, in every block after it, and surface soil water 0.19, 0.19, 0.19, 0.18. At the export 14 of the 200 cohorts carry density; the other 186 are frozen, absorbed into the layer or at exactly zero density. A relative-change criterion under a stochastic driver needs a tolerance above the block-to-block fluctuation, 10 to 20 % here at 50-year blocks, or it never fires; the trace is what to read.
- The window run, 150 years from the export, took 22 s, against 9 s under the survival floor for the reason in the cost paragraph below; the resident's window-averaged $R$ at birth rate 1 is 62.72, the trapezium mean over its 101 arrivals (the plain mean is 62.32; the two differ by the edge cohorts' half weights), with the 200 seeded cohorts at weight zero. The top layer's seed output is not in it: the layer was filled in the burn-in, under the burn-in's weights, and a window run scores only its own cohorts. Counting the layer's seeds read $R = 378.7$; `test-absorb.R` now holds the window's $R$ to its own cohorts.
- One arrival's lifetime output has a coefficient of variation of 1.29 across arrival years, is zero in 31 of 101 years, and has no lag-one autocorrelation (−0.01): a failed year is a failed year, and the correlation time the note worried about is below a year for this stand. The two half windows read 71.6 and 53.8. The relative standard error of a 100-year window mean is 0.13; a 1 % level needs about 16,000 arrival years, a 5 % level about 650. That is the note's §4.5 number, and it says the level is not the thing to resolve: common random numbers for differences, and stratification by the state at arrival, are what the next measurement is about.
- Truncation: a cohort born in the window's first decade had reached 0 % of its final output at age 10, 99.8 % at 25 and 100 % at 50, so 50 years past the window is enough here and the last decade's low mean (11.4 against 62) is a run of failed years, not truncation.

|---|---|---|

| 0.5 year | 0.17 % | +0.10 % |

**Is it generic?** Every step was run on all four models (FF16, K93, TF24, TF24f): a periodic schedule with frozen cohorts on the birth-date coordinate (then by the survival floor, since removed), `run_until_converged()`, snapshots, export, resume into `fitness_window()`, a rare copy of the resident beside it, and `run_mutant()` from the resumed resident. The recording's first row is the resumed state and no step reached it, so it carries no field; the SCM now keeps the resident's field at that row (`resident_start_field`) and the invader stands in it until the first recorded step hands over the next. That was the one instant develop's carried-over field did not cover.

- Frozen cohorts first made FF16 *slower* (7.3 s against 5.0 s over 3000 years): a frozen cohort's height stops while younger ones grow past it, which broke the decreasing-height ordering the fast field build relies on, so every build fell back to a walk per height; FF16's field build is its cost, where TF24's leaf solve had hidden it. With the layer on the height scan leaves frozen cohorts out and the walk steps over them; competition agrees with the old path to 3e-11 at every height, and the canopy top is now the tallest living cohort, which moves outputs at the 1e-6 level by changing the knot grid, not the model.
- $R$ at stationarity is proportional to $1/b$ ($d \log R / d \log b = -1.00000$ over $b$ = 1 to 3, by the retired script `ff16_continuous.R`, [at `c410510b`](https://github.com/traitecoevo/plant/blob/c410510b0162ca701101f58ae64c8f6295e594b8/notes/scripts/continuous-patch-519/ff16_continuous.R); the root-find in `fixed_point.R`'s `landscape` task replaces it): seed production per patch does not depend on the birth rate, the canopy saturating whatever the seed input, so $b^* = 68.87$. But this stand cannot be run at $b \ge 10$: it stops on FF16's density-overflow guard (a cohort at 2.71 m reaching a log density of 868, which the birth-date coordinate should never allow), identically on develop with none of this work, while the same stand runs on the height coordinate and under the default Weibull regime and schedule. A defect in develop, fixed by #662 and merged into #661: a Runge–Kutta stage straddling a dying cohort's rates switching off put a trial log density at +868, and the guard stopped the run where it now rejects the stage. The survival floor had hidden it, by freezing the cohorts that blow up.

**Bounding the cost on the pulsed TF24 stand, measured.** The pilot's stand and pulse series rerun to 200 years by `measure.R` with the top layer at $\varepsilon = 0.05$ (17.57 m; `output/chunks-absorb-0.05.csv`), against no boundary and against the survival floor at 1e-9 while it existed (`output/chunks-retire-1e-9.csv`):

| simulated years | s per year, no boundary | survival floor (removed) | top layer | cohorts with density | frozen | cumulative offspring vs no boundary |
|---|---|---|---|---|---|---|
| 50 | 0.122 | 0.079 | 0.042 | 12 | 39 | 1.3e-5 |
| 100 | 0.281 | 0.096 | 0.052 | 15 | 86 | 2.0e-4 |
| 200 | 0.470 | 0.087 | 0.047 | 14 | 186 | 3.1e-4 |

200 years take 10 s with the top layer, 17 s with the floor and 54 s with neither. The height-only rule is the cheapest here: canopy cohorts reach 17.57 m within a few decades and are absorbed while still alive, and the many that die young reach exactly zero density and are frozen without any floor. The cost per year stops growing once frozen cohorts outnumber live ones, about ten times less than unbounded by year 200. Cumulative offspring production agrees with the unbounded run to 3e-4 at $\varepsilon$ = 0.05, the size the FF16 table predicts for a layer pinned that far below the asymptote.

## Hazards

1. **`rebind_from` copies what `validate()` reads**: the fitness-window fields must be copied too, or the rebound patch runs a different regime with nothing raised. The top layer needs no copy beyond its state, which travels.
2. **Refinement and the top layer do not mix.** `refine_schedule` pairs per-node errors with schedule times; refuse the combination rather than let the pairing drift.
3. **Inherited step size across pulses.** Plan-events' hazard 1 is untouched; every pulse is a leg boundary, and `ode_step_size_max = 0.05` is a measured guard, not a fix.
4. **The queue is built by a linear scan per event** ([node_schedule.cpp:132](../src/node_schedule.cpp#L132)): quadratic at the $10^4$ to $10^5$ events of a long pulsed run. Section 7 says whether it shows.
5. **The absorbing height is a selection on state.** A trait perturbation that changes which cohorts merge makes a pinned-step finite difference disagree with the sweep at that kink, as the leaf's operating-point kinds do; the referee must hold the selection fixed.
6. **Crossing cohorts.** TF24's reserve gate lets a younger cohort overtake an older one. Absorption reads each cohort's own height, so the younger goes first and the older when it arrives; neither waits for the other.
7. **`make_initial_state()` on the birth-date coordinate** stamps every node at time 0 and is refused for more than one node per species; it is not the resume entry point.
8. **`history` under `collect`** is a Patch copy per leg; never on for a long run.
9. **A resumed run is not bit-identical** to a straight one at the seam; say so beside any number that crosses one.
10. **Scored cohorts are never retired, by decision.** A window cohort that never reaches the absorbing height is integrated to the end of the run however small its density: 65 of 101 still integrated at year 350 on the pulsed stand at $b^*$, which makes the window run 2.5 times the cost it had under the survival floor (section 7). Daniel, 2026-10-13: no survival floor for scored cohorts either; the cost is accepted.
11. **A spent top layer is emptied, not left subnormal** ([#666](https://github.com/traitecoevo/plant/issues/666), fixed in #661). The layer carries its density and weights linearly, and at the bottom of the subnormal range a decay step rounds back to the value it started from, so a layer whose inflow stopped never emptied by itself: it pinned `height_max`, and the light field's knots, at the absorbing height, and kept a tree that no longer exists rated at every stage. At each introduction instant a density or weight below the smallest normal double is now put to zero; the seeds it accrued stay. Anything that changes how the layer decays has to keep that.
12. **The introduction grid can make a fixed point a periodic orbit** ([#665](https://github.com/traitecoevo/plant/issues/665)). Between two introductions the field swings; at a cohort a year FF16 at $b^*$ swings by 1.8 % in held $R$, and a field held at an introduction is the top of it. Check a held field inside an interval, by ending the resident's run off the grid, never only at introduction instants, and refine the grid until the swing is below what the comparison needs (section 7).
13. **Merging with #658.** #658 routes `net_reproduction_ratios` and `offspring_production` through a plain-trapezium `fitness_integral()`. Whichever lands second has to carry over `is_arrival_weighting()`, the span normalisation, the top layer's seeds and `birth_scaled`, and a fitness gradient over a window needs the quotient rule for its normalisation. The textual conflict will show; the semantic one is guarded by tests on develop that whichever lands second must pass: the window ratio and offspring production as the normalised window mean (`test-fitness-window.R`), the layer's seeds in the stand's ratio and scaled by the birth rate in offspring production (`test-absorb.R`).
14. **R-side integrals do not read the top layer.** `integrate_over_size_distribution()`, `tidy_species()` and `tidy_patch()` see the nodes only, and `tidy_species()` warns when the layer carries density (a warning, not a refusal, because it runs at the end of a collected run). Read the layer from `species$top_layer` or the snapshots' `top_density` until they do.
15. **A cohort born with no density is frozen at birth** with the layer on, so a species at birth rate zero would read zero per-capita output where it would accrue a little. Refused at introduction (`Patch::push_nodes`) wherever the regime weights the cohort; give a rare species a small positive birth rate.
16. **A TF24 replay pairs recorded leaf solves by position.** The resident's recorded operating points are loaded into the invader's solves in order, and a frozen cohort does not solve, so a resident and an invader with different frozen sets, or a resumed resident with seeded cohorts, pair a solve with the wrong cohort. Part of exact replay of a stand with events ([#668](https://github.com/traitecoevo/plant/issues/668)); a TF24 `run_mutant()` of the resident's own strategy already disagrees for the reasons recorded there.
17. **A resume with no introductions left stops where it starts.** `SCM$complete` counts schedule entries, and an empty residual schedule has none, so such a run never integrates to `max_patch_lifetime`. Pre-existing, and more reachable now; refused when the run begins, so keep at least one introduction ahead of a resume.
